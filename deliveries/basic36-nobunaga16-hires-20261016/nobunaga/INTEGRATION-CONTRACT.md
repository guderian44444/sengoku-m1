# Integration contract

1. `delivery-manifest.json` is the selected-version authority. Ignore stale top-level frame totals and candidate statuses in historical source manifests. Use all 16 keys exactly once. Reverse throw is 16 × 50 ms = 800 ms, not its old 23-frame source.
2. Coordinates are native image pixels, +x right, +y down. Read each frame canvas and preserve it. Do not crop independently, normalize bounding-box heights, or rescale crouched/rotating poses to standing height. Fixed reference ruler: original standing ready 914 native px (manual art measure), with per-clip approved registration preserved.
3. Approved GIF/review PNGs are presentation references. Native RGBA masters are the high-resolution source. Resizing happens once at the target rendering step. Alpha sampling differences versus historical RGB-on-dark-matte rendering are documented per frame.
4. Visible-only layers share the master's canvas and identity transform. Compose body → visible weapon → hand foreground. Reverse uses body → weapon-visible → hand-foreground. These disjoint-pixel layers retain original appearance only when co-located. They are not independent complete body/sword sprites. For charge_release, composite FX back → reassembled actor → FX front. Existing native full weapon/body layers are additional authoring sources, not proof of complete hidden artwork.
5. Frame durations are integer milliseconds and must not be replaced with a generic fixed FPS. Preview GIF disposal/palette are already baked. The manifest stores exact GIF timing and SHA. Hold endpoint equality is checked separately; looping attack GIFs do not imply an engine last→first transition.
6. `native_to_preview` is visual staging only. Legacy source fields called “world” were renderer/presentation coordinates. Never treat those as game-world movement. No engine displacement track is supplied; retain the existing engine contract. Mirror around the existing actor/root convention only after a runtime test.
7. Root/sole/grip/angle metadata is advisory art data. Each record states whether copied, transformed, manually annotated or image-derived. Do not silently wire inferred grip centers to weapon sockets or sole points to collision. Missing grip/axis values remain null rather than fabricated. Weapon front/back depth is authored where available; flattened sources carry only baked visible occlusion.
8. Art event markers describe visible landing, FX stages, loop boundaries and recovery. They are not hitbox activation, damage, gameplay release, collision or enemy attachment events. Keep current gameplay event times until engine integration is explicitly tested. Preserve final sword-guard/idle recovery boundaries.
9. New weapons: choose the target weapon, inspect the per-frame gap list, add hidden body/weapon fill as separate alternatives only where the replacement exposes missing regions, and verify the original approved composite remains unchanged. Do not extend or redraw approved master clips just to recover invisible blade sections.
10. Acceptance before runtime use: verify hashes; run `python tools/verify_delivery.py`; test layer composition; check target-size antialiasing on actual backgrounds; check forward/reverse facing, sockets, hitbox/hurtbox and victim attachment, motion, transition/landing/recovery timing in the real engine. These checks have not been performed in this asset-only task.

## Git handoff

Commit the unpacked asset tree and metadata in the requested repository path. Do not commit the transport ZIP. Each expanded file is below 100 MB; actual largest-file size is in validation-final.json. Keep all previous approved assets available until integration is validated. Historical source aliases and original SHA-pinned artifacts are supplied for traceability; old generator scripts may reference original workspace paths. The delivery verifier is self-contained; full historical generation is not promised as a one-command portable rebuild.
