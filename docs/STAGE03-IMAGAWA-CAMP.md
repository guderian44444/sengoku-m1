## 使用者指定內容

1. 第一大段：警鐘掛高柱並持續響，可由多根支柱支撐。每死一名雜兵，延遲後補一名，維持目標人數；所有支柱破壞才停止本段補兵。
2. 第二大段：多層橫向障礙，必須破壞推進，不設繞路。
3. 第三大段：盾兵、槍兵、遠程兵刻意錯落；前排缺口由後排現有兵實際走來補，新援從入口補後排，玩家須有突破缺口的時間。末尾進大帳。
4. 帳內第一階段：兩名小王 A／B 適度分開，持續補雜兵；兩王都死亡即切第二階段，不以雜兵全滅作切換條件。小王姓名與正式外觀待設計。
5. 第二階段：義元移動更快、可格擋、戰術走位，遠距具放箭與揮刀劍氣兩招，持續補雜兵。

## 結構與不變量

`Stage03Encounter` 控制器承接第三關遭遇階段與人口；第一里程碑先完成警鐘，後續才擴充陣形站位。Battle 保持傷害、碰撞、動畫時序與投射物的權威來源。前兩關未配置此控制器時沿用原流程。

完整關卡預計為 `alarm → barriers → formation → lieutenants → yoshimoto → cleanup → complete`；M2 已接前三段原型。警鐘內部為 `active → draining → complete`，障礙與陣形為 `active → complete`；中止則為 `cancelled`。全局 playing／won／lost 與一般關卡 combat／exit 不另改名；第三關內部階段獨立保存。

- 高鐘只畫在上方，受傷與碰撞目標為地面支柱；鐘與支柱使用 group ID，不以單根破壞就停響。
- 補兵採固定 tick 的有界單人單位預約。`存活雜兵（含進場）＋待補名額 ≤ 本階段目標人數`。每次真實死亡只入列一次，搬移站位不建立補兵單。
- 同一 tick 先結算死亡與目標／階段變更，再入場補兵；停援、切階段、勝敗及重開均取消過期預約。
- 補兵入口、後排站位與補位目的地由資料指定，不能沿用一般進場左右輪流而意外生成在玩家背後。
- 陣形補位有缺口保留與唯一預約；移動受既有碰撞限制，不瞬移、不補滿死亡單位 HP、不把遠程兵變成盾兵。
- 帳內切階段保留玩家 HP、位置、裝備、怒氣與現存雜兵；現存雜兵計入下一階段容量。義元死後先停援，清完餘兵才結算。
- 主機決定 AI、入場、階段與預約。快照保存持續狀態；事件只驅動提示／音效，事件 ID 用於去重。

## 可調原型預設（不是使用者確認數值）

先試兩根支柱、單人 6／雙人 9 名目標雜兵、死亡後 240 tick 補位、每 45 tick 最多准入一名、前排缺口至少 90 tick、小王相距約 260 px。實際值放進第三關資料，依測試調整。有限掉落、危險攻擊協調、目標保持與後撤上限也是原型預設，不更改前兩關規則。

## 多人目標與義元

- 目標選擇只考慮活著且可作戰玩家，保留目標一段時間；死亡／失效立即重選。雙人分攤小王與雜兵壓力，攻擊預備後鎖定瞄準位置。
- 小王使用軟性分離，不為保持距離無限逃離；單人時避免兩名小王同時使用大範圍危險招。
- 義元 AI 分開處理接近、側移、格擋、短退、攻擊與收招；戰術狀態不等於新增一套動畫。後撤有時間／距離上限與冷卻，牆邊側移或迎戰。
- 新增 `boss_arrow`、`boss_sword_wave`；原 `boss_volley` 是鐵砲，不拿它冒充箭。沿用投射物系統，但新招有獨立預告、出手、收招及命中參數。

## 素材與驗收

見 [素材狀態清單](STAGE03-ASSETS.md)。本原型不自動發布遊戲、不合併主線。第一里程碑已接入可單人／雙人試玩的警鐘區；正常章節選單仍只顯示第一、二關。啟動方式、實際通過與既有失敗見 [M1 驗證紀錄](STAGE03-VALIDATION-M1.md)。

實作順序：遭遇與補兵取消 → 多柱警鐘 → 三大段與障礙 → 陣形真實補位 → 雙小王與雙血條 → 義元 AI／兩招遠程 → 同步與回歸。

必測：重複死亡、同 tick 大量死亡、滿額／屍體占位、停鐘／換階段後殘留預約、兩兵搶同一補位、目標抖動、後撤無限循環、兩王同 tick 死亡、義元死亡停援、勝敗／重開取消、前兩關與 Wire 回歸。狀態機測試不能當真人難度或正式美術驗收。

## M1 已接入範圍

- `game/data/stage-03.json` 是 `prototype: true` 的單場鐘區，單獨進入，不自動解鎖下一關。
- `game/core/stage03_encounter.gd` 保存人口、逐人死亡預約、固定右側入口、支柱群組及停鐘狀態。預約與進場兵都計入人口，實體演員達 48 時暫緩准入，每次最多補一名。
- 高鐘沒有攻擊碰撞；地面支柱沿用 Battle 的物件攻擊與碰撞。所有柱斷裂先取消同 tick 到期預約，再讓玩家清除餘兵。
- 警鐘循環由持續快照狀態決定；暫停、全柱破壞、勝敗、離開與重開會停止或暫停聲音，不依賴漏掉的單次事件。
- 據點重開會清除舊遭遇兵與支柱。Wire 檢查預約型別／數量／重複 ID／epoch、支柱歸屬、人口容量與階段一致性；客端輸入不能提交補兵排程。
- `scripts/play-stage03-alarm.ps1` 啟動專用入口並隔離玩家資料；專用入口停用角色進度寫回。玩家角色、敵人、底圖及配樂沿用基底；支柱、鐘與鐘聲是占位。

M1 警鐘原型已在 M2 擴成連續三段。M3 已接帳內雙小王；義元與完整線上連線驗收仍待後續里程碑，不能把目前原型當完整第三關。

## M2 已接入範圍

- 第三關資料現有三個獨立場景，各一個專用遭遇：警鐘 → 多層木障 → 帳前陣形。第一、二段清除後沿既有 GO／全員出口流程推進；第三段全員穿過帳門標線後結束目前原型，帳內尚未製作。
- 三層木障以整條行走帶的實際碰撞阻擋，必須逐層擊破；上／下緣、跳躍與衝撞均無繞行通道。沿用 Battle 的物件受傷、破裂及碰撞開通。
- `Stage03Objectives` 是第三關遭遇控制器的障礙／陣形實作。前排和後排以不同 x／y 偏移排列盾槍兵、槍兵與弓兵，非整齊格線。單人 6、雙人 9 兵仍是可調預設。
- 前排死亡後至少保留 90 tick 缺口，再為該位置預約一名後排現有士兵。預約只改位置歸屬，不改實際座標、HP 或兵種；士兵每 tick 經既有移動／碰撞前移。每名候補與每個位置只有一份預約。
- 新增士兵只從畫面外走入騰出的後排。大量同時死亡時，前排尚未綁定後排位置的補兵單不會擋住已能准入的後排單，避免全滅後停擺。預約與進場兵都計入人口上限，每次准入一名。
- 玩家突破前線後，主機保存 `breached` 持續狀態；守軍解除定點守位，轉身、追擊並沿用既有近戰／遠程攻擊。全員抵達帳門時取消預約，不以清光存活士兵作完成條件。
- Wire 檢查位置／候補唯一歸屬、補兵只能指向後排、舊 epoch、錯誤型別、障礙群組及完整碰撞深度。主機快照保存持續狀態，省略事件亦可完整還原預約。

M2 的驗證、原生畫面及本次提交清單見 [M2 驗證紀錄](STAGE03-VALIDATION-M2.md)。所有占位、缺口／增援時長與通行座標均是原型預設，沒有把它們當成使用者最終確認的數值。

## M3 已接入範圍

- 帳前陣形突破後依 GO 全員走至帳門，進入第四個帳內場景；轉場保留玩家 HP、怒氣、裝備與收藏，外場敵兵依既有換場流程清除。

- 帳門布簾、A／B 大小與字標、雙血條使用現有素材與可辨識占位。正式人物、招式美術與語音未宣告完成。
