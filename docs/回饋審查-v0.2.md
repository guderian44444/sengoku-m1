# 第一輪回饋審查與 M1 決策

查核：2026-10-09。直接讀取既有私人網站的正式評論，共 5 則，讀取時無分頁遺漏。其他 6 區尚無評論，不解讀成已正式認可，但不阻擋可逆的 M1 原型。

## 結論

沒有需要停止開工的矛盾。保留六主角／24戰場長期框架，先實作一段短關卡驗證戰鬥與兩台電腦直連。桌面程式提供原生輸入與直接 UDP 網路能力；穩定性仍取決於架構及測試，不因改成 EXE 就自動成立。

## 可直接採用的起始規格（仍可評論修改）

- 輕擊快速連段；重擊較慢、命中使敵人倒地；位移擊退在手感階段調整；重擊按住約 0.58 秒放開成蓄力。數值先作可玩性起點。
- 怒氣獨立於 HP，命中／受擊累積。滿怒氣才能放必殺，判定由主機執行。
- 必殺先使用短起手與清楚範圍；敵人於有效出招前仍可離開範圍。演出停頓不得讓全隊等待數秒；M1 核心先驗證可躲避，不做電影式長演出。
- 未來雙人合技：角色或武器條件＋雙方怒氣＋距離＋雙方確認，由主機扣資源及觸發。此為 M2 項目，M1 不假稱已做。
- 初期簡裝；武器／護甲分層附著在相同握柄與身體基準。掉落、所有權、換裝與能力變動由主機判定。專長加成與劇情裝備留在後續內容階段。
- 男性不得批量變成美男臉；女性柔美可讀剪影、針毒是演義，服裝年代與人物真實擅長武器另做史料核對。
- M1 不提供背包、存檔遷移與完整角色故事。離開本次關卡不保存進度，介面明示。

## IP 直連的邊界

- 同 LAN：客人輸入主機私有 IP 與相同 UDP 埠（預設 27860）。首次 Windows 防火牆是否允許由使用者自行決定，程式不修改防火牆或路由器。
- 跨網路：需要可到達的公網位址與可能的 UDP 轉發。私有位址不能從外網直接到達；CGNAT、企業網路或封鎖 UDP 都可能失敗。
- 首版無中繼、無自動 UPnP、無配對平台。受到 NAT 限制的網路不保證可連。
- M1 採主機權威：客端僅傳移動／按鍵，主機計算傷害、拾取與結算。先使用狀態快照，未實作預測／rollback；不能承諾高延遲外網手感。
- 開局比對版本與戰鬥內容 SHA-256；非法按鍵／序號／玩家來源拒絕。斷線中止本局並顯示原因，無主機移轉。

## 素材一致性生產關卡

每角色先完成：正側背設定圖、年齡／體型、臉髮不可變特徵、色票、武器尺度、腳底原點、握柄錨點。身體／裝備／武器各層使用同一幀 ID。先驗證待機、移動、輕重、跳躍、受擊與換裝一組，再批量畫其他招式。AI 概念圖不等於可直接使用的動畫。

## M1 驗收與缺口

這一階段要有兩種差異角色、三波短關卡與首領、輕重與蓄力、跳躍／抓投、怒氣必殺、食物／武器／護甲拾取、勝敗與重開、鍵盤與預設搖桿映射、IP 建立／加入／錯誤與斷線訊息。

自動化可以驗證核心邏輯、正常輸入通關、版本拒絕、同機雙程序通訊与畫面能渲染。**兩台實體 Windows 電腦 LAN 通關、實體搖桿、聽覺與打擊手感，仍需真機試玩。** 未完成這些驗收前，不能宣稱連線或搖桿品質已驗收。
