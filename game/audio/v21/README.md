# v0.21 場景與將領循環配樂

四首原創程序作曲，樂器以合成方式產生；沒有擷取原作旋律、錄音或第三方音樂片段。

| 檔案 | 場合 | 速度／長度 | 配器與節奏 |
|---|---|---|---|
| `bamboo-loop.wav` | 竹林、池石庭園 | 72 BPM／53.33 秒 | 柔和低簫長句、稀疏撥弦、小鈴；沒有戰鼓，保留呼吸與留白 |
| `town-loop.wav` | 山腳市集 | 124 BPM／61.94 秒 | 鈴鼓、金屬小鈴、木拍、三味線切分問答 |
| `miniboss-loop.wav` | 存活的小王 | 152 BPM／50.53 秒 | 太鼓重拍、締太鼓滾奏、反覆低弦 |
| `boss-loop.wav` | 存活的關底大王 | 174 BPM／44.14 秒 | 大太鼓、左右對鼓、急促低弦、短高笛回應 |

山道沿用 v18 `siege`，寨門、兵糧營與內室的普通敵波沿用 v18 `castle`。選曲依「存活大王 → 存活小王 → 區域音樂」優先；將領倒地但未死亡不退曲，死亡後回到區域音樂。各次切換使用既有 1.4 秒交叉淡入。場景資料與選曲邏輯分別在 `game/data/stage-01.json`、`game/render/combat_audio.gd`。

全部為 44.1 kHz、16 bit、雙聲道完整循環。尾音與殘響繞回檔案開頭，沒有結尾淡出或人工插入靜音。簫曲的 RMS 上限較低，保留幽靜區域與戰鼓區域的強弱差別；遊戲內仍使用獨立 Music 音量。

以具有 NumPy、SciPy 的 Python 執行 `scripts/generate-stage-bgm-v21.py` 可重建四首音樂與 `music.json`；加上 `--verify` 僅檢查現有檔案。Manifest 包含可重建的音符／打擊事件、seed、SHA-256、長度、振幅與循環邊界量測。`game/tests/test_music_v21.gd` 驗證實際播放、跨循環、將領選曲與新道具事件音效；`test_audio_v20.gd` 驗證所有音樂兩次跨界及音量保存。

波形、混音路由、原生播放已自動檢查。樂器真實感、主觀氣氛與耳機／喇叭實際聽感仍待真人試聽。
